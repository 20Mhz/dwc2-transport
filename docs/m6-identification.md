# M6 device identification (database 1.0.0)

Source inspection began at SDK 5cf4655 and HostLab 6df8d90. SDK tree was clean;
HostLab had the pre-existing untracked docs/evidence/m4-20261102.zip and was
not changed. The prior Apple TV bundle's SHA256 manifest verifies. It records
25 async reads, five process restarts and ten complete traced control requests
on the physical 6.12.47+rpt-rpi-v6 kernel. The device is still accessible.

The canonical [USB ID registry](https://github.com/usbids/usbids/blob/5eb613762db1e34b9218da63a88f22dd26f743c5/usb.ids)
labels 05ac:12a7 **TV Device**. This documents a product-family association,
not a mapping to a particular generation or model. Apple's
[model identification page](https://support.apple.com/en-us/101605) lists
A1427/A1469 as third-generation Apple TVs, identified by physical labels;
it does not establish a USB PID mapping. A1427 is owner-supplied context.
Do not infer the physical model, firmware version, security state or OS health
from PID, product string or bcdDevice. USB descriptor IDs are not authentication.

The observed interface is class ff, subclass fe, protocol 02 with two bulk
endpoints. These match the [usbmuxd interface definitions](https://github.com/libimobiledevice/usbmuxd/blob/3ded00c9985a5108cfc7591a309f9a23d57a8cba/src/usb.h),
and the PID lies in its recognized 1290..12af range. We report
**usbmux-compatible (descriptor inference)**. No usbmux protocol traffic or
Apple vendor request is issued, so functional compatibility remains untested.
We intentionally do not copy usbmuxd's mode heuristics or invoke it.

The public [libirecovery mode enum](https://github.com/libimobiledevice/libirecovery/blob/046344f7fe4413e42e71046a34230850be3f758a/include/libirecovery.h)
labels 1227 as DFU, 1280..1283 as recovery, 1222 as WTF and f014 as port DFU.
Those are shared Apple mode IDs, not Apple TV model evidence. Unknown Apple
PIDs remain unknown; non-Apple vendors never inherit these mode classifications.
Observed 12a7 is classified `apple_tv_usb`, explicitly without a verified model
or a claim about its exact boot/OS state.

`data/device-identification-v1.json` stores schema/version, source references,
source revisions, confidence and caveats. The small committed C table is
generated by `scripts/generate-device-db.py`; `--check` detects drift. The
Python observer reads the same JSON database. These belong to the diagnostic
application, not the stable transport ABI. No external source code is linked.

Standard descriptor layouts are referenced against Linux
[ch9.h v6.12](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/usb/ch9.h).
The inspector validates lengths before emitting structured data, reports
configuration attributes/power, interface triples and endpoint directions/types,
and bounds configuration/string reads. Serial string indices, including aliases
shared with other roles, are skipped unless `--include-serial` is explicit.
